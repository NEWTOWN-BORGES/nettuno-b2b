Documentação Técnica

Guia de integração da Risk API V1 e do Nettuno Shield SDK em menos de 10 minutos.

1. Início Rápido (10 Minutos)

O Nettuno fornece uma infraestrutura unificada de avaliação de risco e selos de confiança comunitários. O SDK frontend renderiza o Shield usando o design system nativo do vosso marketplace sem conflitos visuais. 

<!-- Carregar o SDK Vanilla JS (Zero dependências) -->
<script src="https://nettuno-e6036.web.app/sdk/nettuno.js"></script>

<script>
  // 1. Inicializar cliente
  const nt = Nettuno.create({ apiKey: 'nt_live_...' });

  // 2. Obter o Shield do anúncio (0 créditos — leitura rápida/cache)
  const shield = await nt.getShield('anuncio_olx_12345');

  // 3. Montar o Escudo no anúncio (adapta-se ao CSS do vosso site).
  //    Clicável por omissão: abre o painel completo (voto + partilha +
  //    abas SINAIS/CONTACTO/INTERAÇÃO/RESULTADO) — o mesmo da extensão Nettuno.
  nt.mountShield(document.getElementById('shield-container'), shield);
</script>

O Shield, o cache, a votação e o reporte de sinais da comunidade são gratuitos. Apenas requestAnalysis(listingId, listingData) consome 1 Risk Unit, e só quando explicitamente pedido — ver secção "Modelo de Consumo" abaixo. Para um widget de voto isolado (sem o painel completo), use nt.mountVotePanel(el, listingId) à parte.

1.1 Modelo de Consumo

  • getShield / batchShield / mountShield — 0 créditos.
  • vote / mountVotePanel — 0 créditos.
  • requestAnalysis — 1 Risk Unit por chamada, processada de forma assíncrona pelo Risk Engine.

Isto significa que podem colocar o Shield em milhões de anúncios sem gastar créditos: os créditos só são debitados quando pedem explicitamente uma Análise Profunda.

2. Arquitetura de Segurança Recomendada

🔒
Recomendação de Produção: Nunca exponha a sua chave nt_live_... em código JavaScript público no navegador.

O fluxo corporativo seguro consiste em chamar a Risk API a partir do vosso backend ou servidor Next.js/Node/Python, e passar apenas o objeto de resultado para o navegador renderizar o Shield: 

[ Navegador ] ───► [ Backend Marketplace ] ───► [ Nettuno Risk API V1 ]
                        (nt_live_secreto)            (Cálculo & Quota)
                              │
                    Objeto de Risco Sanitizado
                              │
                              ▼
                     [ Nettuno Shield SDK ] (Renderiza com vosso CSS)

3. Classes CSS Públicas & Custom Properties

O SDK emite elementos com classes estáveis e previsíveis para que o vosso time de frontend possa estilizar livremente em CSS: 

/* Estilização via Classes Públicas */
.nettuno-shield {
  font-family: var(--font-brand);
  border-radius: var(--radius-md);
}

.nettuno-shield--safe {
  background: var(--color-success-bg);
  color: var(--color-success-text);
}

.nettuno-shield--risk {
  background: var(--color-warning-bg);
  color: var(--color-warning-text);
}

/* Ou mapeando variáveis diretamente */
.nettuno-shield {
  --nettuno-bg: var(--card-bg);
  --nettuno-text: var(--text-color);
  --nettuno-radius: 8px;
}

O painel completo que abre ao clicar no Shield (voto, partilha, abas de sinais) usa classes as-* estáveis (as-v3-modal, as-brutal-pill, as-like-btn/as-dislike-btn, as-v3-card, as-v3-tab, entre outras) — o mesmo painel usado na extensão Nettuno. Também pode ser estilizado com CSS nativo.

4. Endpoint de Teste Sandbox & Chaves `nt_test_`

Para desenvolvimento, testes unitários e pipelines de CI/CD sem consumo de créditos reais, utilize uma chave do tipo nt_test_... ou utilize o endpoint de simulação determinística: 

POST https://nettuno-e6036.web.app/v1/test/analyze
Authorization: Bearer nt_test_...
Content-Type: application/json

{
  "listingId": "test_ad_1",
  "scenario": "RISK" // "SAFE" | "TRUSTED" | "RISK"
}

5. Tabela de Códigos de Resposta HTTP

200 OK                  ► Análise processada com sucesso. Headers de quota e cache incluídos.
401 API_KEY_REVOKED     ► A API key foi revogada pelo utilizador no dashboard.
401 UNAUTHORIZED        ► Chave ausente ou hash SHA-256 não reconhecido.
402 QUOTA_EXCEEDED      ► Limite mensal de créditos do plano atingido (hard limit).
429 RATE_LIMIT_EXCEEDED ► Frequência de requisições excedida (>120 req/min por omissão).
